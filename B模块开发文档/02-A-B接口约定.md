## 2. 所有权和身份

A是任务事实的权威来源。B不写A数据库；B给出缺失/冲突清单，A更正后递交新版本。

用户调用使用可信令牌；服务调用使用服务身份。A代用户查询时携带可验证的用户上下文，B检查服务范围与用户范围交集。不得从请求正文的org_id/project_id推导调用者具有权限。

B不复制账号密码系统，保存身份映射和本模块角色。独立开发用显式mock身份，正式配置必须拒绝mock。

## 3. 知识查询

`POST /integration/v1/knowledge/query`

请求示例（示例ID均为占位，不是实际项目）：

```json
{
  "request_id": "req-demo-001",
  "project_id": "project-demo",
  "task_id": "task-demo",
  "scene_code": "lifting_supervision",
  "question": "本次吊装旁站需要重点关注哪些内容？",
  "context": {"object_type": "lifting", "stage": "preparation", "conditions": {}},
  "output_types": ["checkpoints", "cases"],
  "limit": 5
}
```

`task_id`可空；project_id必须属于已授权范围。limit服务端设上限。context不能覆盖系统提示或授权。output_types枚举由B00冻结。

响应包含query_id、status、knowledge_release_id、answer_blocks、checkpoints、cases、citations、missing_conditions、warnings。

每个answer_block包含text和citation_ids。每个引用包含citation_id、knowledge_revision_id、evidence_id、source_title、locator、review_status。引用链接通过B受控证据接口解析，不返回本机绝对路径或永久公开下载地址。

status建议：answered、insufficient_evidence、degraded。生成失败但检索成功时可degraded返回证据列表；检索也失败时返回明确错误。

双方需商定响应超时；B记录实际耗时，不在没有环境测量时承诺延迟。A应支持无答案、部分证据和超时状态。

## 4. 任务包提交

`POST /integration/v1/task-packages`

Header包含Idempotency-Key。首版JSON完整快照，附件分离，不传base64大文件。必要字段：

| 字段 | 类型/规则 |
|---|---|
| schema_version | 字符串，首版1.0 |
| producer | 注册来源系统标识 |
| package_id | 来源包唯一ID |
| task_id | A稳定任务ID |
| package_version | 正整数，递增 |
| exported_at | 带时区ISO时间 |
| project_id/org_id | 稳定ID，与调用权限核对 |
| scene_code | 注册场景码 |
| task | 任务名称、状态、实际时间等；未知保持null |
| participants | 人员ID和任务角色数组 |
| events | 过程事件数组 |
| issues | 问题、整改、复核快照 |
| attachments | 附件清单 |
| data_completeness | 各类数据完整、缺失或不适用的明确状态 |
| is_demo | 布尔，演示数据显式标记 |

事件最小字段：event_id、event_type、occurred_at（允许null）、actor_id（可空）、actor_role、related_object_id、payload、evidence_refs。未知事件保留原始数据并显示兼容性警告，不擅自映射为已知事实；核心枚举行为由B00明确。

首版事件：task_started、inspection_recorded、issue_created、rectification_submitted、review_rejected、review_accepted、task_completed。

缺少实际时间不使用exported_at替代。空事件数组可接收为资料型任务，但不得宣称已支持完整过程复盘。事件内部引用必须可解析，否则返回校验错误或明确的缺失状态。

包大小、附件数量、文本长度在B00给出可配置默认限制并写入合同说明，不能无限接收。

## 5. 接收、版本、幂等

首次受理202，响应receipt_id、job_id、status、status_url、replayed=false；重复提交命中既有记录返回200、原receipt/job和replayed=true。建议状态：
received→validating→processing→ready；失败failed，撤回withdrawn。

`GET /integration/v1/task-packages/{receipt_id}`返回状态、validation_errors、missing_fields、retrospective_id（尚未生成时null）。

唯一约束：(producer,task_id,package_version)、(producer,package_id)。
内容哈希使用RFC8785 JCS规范化后SHA-256；仅排除exported_at和附件access_ref。令牌只能在Header。package_id、版本、附件哈希及数组顺序参与内容身份，同版本重试必须稳定。细节和固定样例已在B00交付。

- 同任务版本、同内容：返回原receipt，不重复排队/产出。
- 同任务版本、不同内容：409。
- 同幂等键、不同内容：409。
- 区分最新接收版本与当前可用版本；新版本处理ready后才提升当前可用版本，失败不能替换原可用版本；旧版本保持可追溯。
- 旧版本晚到可归档，但不覆盖当前版本。
- 请求超时后A先按幂等键重试获取原结果，不产生第二份包。
- 队列按至少一次执行设计；业务唯一约束和事务保证幂等。

## 6. 附件

附件字段：attachment_id、sha256、mime_type、size、evidence_type、access_ref。
evidence_type区分现场照片、文字截图、原始文档、视频、其他；未知类型保留未知，不能自动当现场照片。

access_ref首版草案固定为connector_id/object_id两个受控标识。不得执行包中任意URL下载；不得接受任意Windows路径。签名链接由可信connector运行时获取，必须约束来源、期限、重定向、大小，并允许链接过期后重新取件。

首版B可下载必要附件到受控存储，校验哈希后入库。权限和来源关系不能因复制而丢失。部分附件失败保留可处理内容并显示缺失；涉及该附件的结论不能假装有证据。

## 7. 撤回及权限变化

`POST /integration/v1/task-packages/{receipt_id}/withdraw`
正文reason必填，支持幂等。撤回权限必须核对。

在线检索、证据查看和新出题立即阻断已撤回来源；后台标记相关知识、复盘和题目需停用/复核。历史审计保留；学习成绩保留但不向无权限用户泄露原题和证据。撤回不能仅靠删除向量完成。

重新提交更高版本不自动解除旧版本撤回；新版本按权限及审核重新发布。

- [ ] 用户身份、服务身份及越权请求。
- [ ] 正常查询、无证据、模型失败、引用打开。
- [ ] 正常包、缺实际时间、缺附件、未知事件。
- [ ] 重复请求、同版本异内容、新旧版本乱序。
- [ ] worker中断重试、附件校验失败、令牌/链接过期。
- [ ] 撤回后检索、缓存、证据和题目停止新增使用。
- [ ] A事实修改后递交新包，B旧复盘仍可追溯。
