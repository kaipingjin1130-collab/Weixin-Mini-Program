## 页面

| 路由 | 内容 |
|---|---|
| `/retrospectives` | 模式、来源、版本、审核状态 |
| `/retrospectives/{id}` | 实际时间线、事实摘要、发现、证据、建议 |
| `/retrospectives/{id}/review` | 修改、逐项确认、退回、批准、转经验 |

## 表

| 表 | 字段/约束 |
|---|---|
| retrospectives | mode、task_package_id或固定历史来源集合、current_revision、scope |
| retrospective_revisions | parent_id、version、summary、timeline、findings、suggestions、template_version、model_ref、state、row_version |

findings项包括type、text、claim_kind（fact/inference/suggestion）、event_refs、evidence_refs、review_state。首版结构化JSON数组即可；事实和建议不能合并成不可追溯的大文本。

## 接口

前缀`/api/v1`：
`POST /retrospectives`、`GET /retrospectives`、`GET /retrospectives/{id}`、
`PATCH /retrospectives/{id}/draft`、`POST /retrospectives/{id}/submit-review`、
`POST /retrospectives/{id}/publish-experiences`。
审核复用`/reviews/{id}/approve`和`request-changes`。
publish-experiences只创建知识候选草稿，不能跳过知识审核；响应明确返回草稿ID。

## 实现步骤

1. 固定来源包/历史记录版本及流程模板版本，计算输入指纹。
2. 按真实时间构建时间线；缺时间事件单列，不能随意插入具体时间。
3. 若有明确期限及适用规则，计算超期；没有期限不输出超期结论。
4. 对照流程模板生成“有记录/缺记录/不适用”，模型解释必须引用证据。
5. 生成草稿，经负责人审核后可转经验；实际流程与建议流程分栏显示。
6. 新任务包生成新复盘版本，旧版不改变；来源撤回后阻断新发布。

## 验收标准

- [x] 已知事件顺序正确；同时间事件稳定显示，未知时间不伪造。
- [x] 事实结论引用有效事件或证据，推断和建议单独标识。
- [x] 没有期限不判超期，没有完整轨迹不生成虚构持续时长。
- [x] 人工修订不被重跑覆盖，旧版本审核不适用于新内容。
- [x] 重复转经验不重复产生候选条目。
- [x] 撤回来源后不能继续生成可发布经验。
- [x] 复盘页面可从发现打开对应证据，并执行退回/修改/重审。
