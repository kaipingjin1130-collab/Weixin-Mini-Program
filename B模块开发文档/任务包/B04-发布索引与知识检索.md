## 给AI的执行指令

执行B04。先读[公共设计](../01-平台设计与公共执行约束.md)、[A/B合同](../02-A-B接口约定.md)、B00机器合同和B03实际代码。实现从已批准知识生成发布快照、建立索引、检索并提供证据化回答。

直接使用pgvector及其Python集成，不自建向量数据库或引入重叠RAG平台。知识查询与权限、证据服务共用一条实现，避免内部搜索和A接口逻辑分叉。

## 页面

| 路由 | 内容 |
|---|---|
| `/knowledge/library` | 已发布卡片，按场景/项目/类型筛选 |
| `/knowledge/{id}` | 内容、适用范围、依据状态、来源、历史版本 |
| `/releases` | 发布批次、构建进度、失败、激活状态 |
| `/search` | 查询、结果列表、答案、引用、缺失条件和反馈 |

## 表

| 表 | 字段/约束 |
|---|---|
| knowledge_releases | version、state、index_config、published_at、active_scope |
| release_entries | release_id、knowledge_revision_id；组合唯一 |
| search_chunks | revision_id、chunk_version、text、keywords、metadata、scope |
| embedding_sets | model、model_version、dimension、chunk_strategy、state |
| chunk_embeddings | chunk_id、embedding_set_id、vector；组合唯一 |
| search_runs | query、parameters、release_id、result_refs、latency、model_ref、feedback |

不同模型/维度使用不同向量集合和匹配索引；具体分表/分区方式按选定维度落地，不能强行写入固定维度的同一列。日志只存必要信息，查询正文按权限和保留策略管理。

内部`/api/v1`：

`POST /knowledge/{id}/withdraw`、`POST /search`、`POST /search/{id}/feedback`。
集成`POST /integration/v1/knowledge/query`遵守B00合同。

## 实现步骤

1. 从approved版本生成固定发布集合，计算切分和模型配置标识。
2. worker构建索引并记录失败项；完成校验后事务性切换active版本。
3. 权限、来源可用性、发布状态、场景条件参与检索过滤。
4. 精确术语/标准编号检索与向量检索合并；明确中文分词，不假设PostgreSQL默认支持中文语义。
5. 重排可选，先评测是否有收益；生成模型只使用授权证据。
6. 每个事实性答案块关联引用；无证据返回不足，生成失败允许只返回检索结果。
7. 缓存键带用户授权范围/版本及发布版本；撤回时在线检查仍阻断旧缓存内容。

## 验收标准

以下勾选限定为本地模拟流程范围；真实语义模型、生成模型超时及实际附件联调不在本次验收内。见[实际验证记录](../../b-risk-knowledge/reports/B04-validation.md)。

- [x] 未发布或未授权知识不进入普通查询和答案。
- [x] 固定样例验证标准编号精确查询与表达变化的相似案例查询。
- [x] 返回的引用真实存在、可授权打开，模型不能创造证据ID。
- [x] 无证据、模型超时、索引失败显示明确状态。
- [x] 新发布构建失败不破坏现有版本；激活不会暴露半成品。
- [x] 切换模型建立新集合，不混用向量；记录重建时间。
- [x] 来源撤回/撤权立即停止返回正文、摘要和附件。
- [x] 报告固定评测集命中情况及实测耗时，不提前承诺准确率。
