# 复用与开源清单

本清单是选型参考，不表示依赖已经安装或在本项目验证。版本、许可证、模型权重授权和运行条件在实际引入时核验并锁定。不为“有开源项目”而引入重叠平台。

## 1. 优先复用已有资产

| 资产 | 可复用内容 | 禁止直接假定 |
|---|---|---|
| governance_hub | 原始/候选/生效字段、人工修订优先级、来源ID、图片关系 | 其数据库可以被B写入，或数据都已审核 |
| 历史CSV | record_id、report_id、定位、依据状态、图片类型、记录种类 | 25,814条就是独立隐患或金标准样本 |
| 机场Excel | 结构化字段、嵌入图片关联规则、依据标识 | 与CSV及工作台互不重合 |
| third-party-inspection | FastAPI、解析及检索相关已有实现 | 声明了依赖就代表能力实际可用 |
| work management | 合适的React组件和业务交互模式 | 可直接复用整个账号/业务数据库 |

先少量验证再迁移可复用逻辑，保留来源说明。不复制旧项目环境、密钥、日志、数据库和完整业务资料进入新代码仓库。

## 3. 不重复造轮子的边界

- 不重建治理工作台全套编辑系统，B只补知识发布所需质量判断。
- 不自研消息队列、向量索引引擎、账号密码系统、通用文档解析器。
- 不额外搭完整LMS，首版只做题目、学习包、作答和反馈。
- 不同时部署Dify、RAGFlow、自建检索平台等重叠系统。未来确有现成能力优势时先比较成本。
- 不为了扩展性提前拆微服务；接口、版本、模块边界先落实。
- 不把外部组件的生成内容视为可信指令；报告中的文字只作为数据和证据。

## 4. 给AI的组件引入指令

读取项目现有依赖和运行环境，只引入当前任务需要的组件。说明它替代了哪部分自研、增加哪些运行依赖。使用当前官方文档核对API和许可证，锁定实际验证版本。提供最小能力验证，记录失败与替代依据。禁止把安装完成等同于功能完成，禁止未经授权将业务样本发送给外部演示服务。
