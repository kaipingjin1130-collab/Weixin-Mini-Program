# 质量安全小察 · 小程序现场端与网页协同平台

## 2026-10-22 报告中心整改与归档入口

网页工作台左侧新增“整改复核”和“成果归档”。已提交的巡查报告可在“整改复核”填写成果接收人和办理期限，确认接收报告后发起后续办理；同一报告重复进入会复用已有任务，不重复生成问题。原报告、签名和照片保留，问题的类别、部位、依据、建议及各自照片关联带入后续任务。

办理顺序：分派整改人和复核人 → 上传整改证据并提交回复 → 复核销项或退回 → 全部销项后生成正式成果 → 登记接收意见 → 归档。“成果归档”集中显示待归档任务及已归档成果，并提供最终报告、归档包下载。无隐患报告可直接生成成果，再接收归档；草稿须先提交。后续办理仍受项目角色和状态校验限制。

地址：`/#rectification`、`/#archives`；作业协同任务支持 `/work?task=任务ID&section=archive` 直接定位成果办理区域。升级需同时更新 `server.py`、`workflow.py` 和 `web/`，重启服务后需重新登录，保留原数据目录。

## 2026-10-20 开发者 A 升级

当前版本按“现场端 + 网页平台 + 共用后台”划分职责：

- **微信小程序**：执行平台派发任务，或在有检查权限的项目自主发起临时巡查；查看资料、检查准备清单、拍照／录音、草稿与确认记录、登记现场问题、生成现场简报 Word、上报平台、查看接收及退回反馈。
- **网页平台 `/work`**：项目、账号与成员分工、任务建立、现场材料接收／退回、问题分派、整改回复、复核退回与销项、正式报告 Word／HTML、浏览器打印 PDF、交接接收、归档、补正与版本化数据包导出。
- **共享后台**：两端使用同一服务地址和数据库。小程序保存成功后，平台刷新即可读取；不需要导入导出来同步这两个客户端。交给开发者 B 时才使用独立任务包。

电脑打开 `http://127.0.0.1:8765/work`。手机小程序填写电脑的局域网地址，如 `http://192.168.1.147:8765`（以当前 IP 为准，不要加 `/work`）。

管理员账号 `admin`，密码仍使用 `data/local-password.txt`。管理员在网页平台创建成员账号并加入项目。成员账号需至少 12 位密码；密码使用独立盐及 PBKDF2 保存。原数据不删除，数据库启动时自动增加新表。

## 原版巡查工作台

基于参考 Excel 第一页的业务界面，从零构建。包含原生微信小程序客户端、本地 Python + SQLite 后台，以及无需小程序账号即可使用的浏览器工作台。没有接入云存储、语音识别或 AI 收费接口。

## 在本机开始试用

1. 确保已安装 Python 3.10 或更新版本。本机已有 Python 3.13。无需 pip 安装依赖。
2. 双击 `start-local.cmd`，保持窗口运行。
3. 用记事本打开首次启动生成的 `data/local-password.txt`，复制密码。
4. 浏览器打开 http://127.0.0.1:8765 ，输入密码。
5. 项目管理 → 填写合同与项目名称 → 创建项目 → 生成巡查编号 → 填写参与人员。
6. 开始上报 → 填写检查人、日期、范围 → 添加隐患 → 填分类、部位、描述 → 直接拍照或选择照片 → 手写签名 → 保存草稿或提交。
7. 报告中心打开已提交报告 → 下载 Word，或使用浏览器“打印 / 保存 PDF”。PDF 是浏览器打印，不是服务器 PDF 转换。

源码包首次启动没有预置项目和报告。本次本机界面验收留下了一个明确标注“功能验收示例合同（非真实业务）”的项目及草稿，照片为上传测试图，仅供试用。知识库内 5 条内容明确标为演示检查提示，不是法规标准，不可作为正式规范引用。

如果没有电脑摄像头，可上传 JPEG / PNG 照片体验完整流程。浏览器实时摄像头需要 localhost 或受信任 HTTPS 环境及用户授权。手机浏览器访问普通局域网 HTTP 时，实时相机可能不可用；选图入口在部分手机支持拍照，但是否显示由手机决定。

## 导入微信开发者工具

1. 安装官方微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 导入 `miniprogram` 文件夹。当前配置 `touristappid`，用于无账号时尝试游客 / 测试模式。游客模式能力取决于工具版本，不保证可真机预览。
3. 开发者工具“详情 → 本地设置”中，开发调试时启用“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。项目配置中也已关闭本地 URL 校验。
4. 启动本地后台。模拟器登录页的服务地址填写 `http://127.0.0.1:8765`，密码从 `data/local-password.txt` 获取。
5. 小程序支持项目和编号管理、知识查询收藏、问题采集、草稿、签名、报告查看、复制及同编号合并、Word 下载预览。

### 手机直接拍照

原生客户端在“直接拍照”按钮使用 `wx.chooseMedia({mediaType:['image'],sourceType:['camera'],camera:'back'})`，明确调用手机相机；“选择照片”单独使用 `sourceType:['album']`。

要真正使用手机微信验证，还需要：

- 自己有权限的小程序 AppID，将 `project.config.json` 的 `appid` 替换为真实值，添加开发者 / 体验成员。
- 在微信后台按实际接口配置用户隐私保护指引，说明相机、照片和签名用途；按当前平台提示完成声明和授权。首次拍照由用户授权。
- 停止仅本机模式，运行 `start-lan.cmd`。电脑和手机连接同一可信 Wi-Fi。
- `ipconfig` 查电脑 IPv4 地址，例如 `192.168.1.10`；手机登录页填 `http://192.168.1.10:8765`。手机的 127.0.0.1 指向手机自身，不能使用。
- 按需要在 Windows 防火墙中允许 Python 的专用网络访问；不要开放到公网。此次未自动更改防火墙。
- 使用开发者工具真机调试，按当前工具 / 微信版本开启相应调试选项。仅在电脑勾选“不校验域名”不代表手机普通预览自动可访问 HTTP。
- 若当前真机环境拒绝局域网 HTTP，应使用受信任 HTTPS 和已配置的合法域名，不能通过关闭正式版校验解决。

这是一套本地后台部署方案。正式发布的微信小程序仍需要微信账号、备案、审核、合法域名和相应网络配置；不能把整个微信运行环境完全离线部署到电脑。本机暂未安装微信开发者工具，交付时需如实区分源码检查与真机验收。

## 数据、认证与备份

- 数据：`data/inspections.sqlite3`，照片和签名：`data/uploads/`。
- 首次生成随机密码保存在 `data/local-password.txt`。可通过环境变量 `QAXC_PASSWORD` 覆盖，不要把该文件提交到 Git。
- 所有业务 API、照片和报告下载都要求登录。会话24小时有效，服务重启需要重新登录；有基础登录频率限制。
- 本版为共享管理员试用空间，登录用户能看到全部项目。不是生产环境的多用户权限系统。
- 正式报告保存生成时的项目名称等快照；修改项目不改变旧报告。草稿使用 revision 防止另一窗口静默覆盖。
- 备份：停止后台后复制整个 `data` 文件夹。恢复：停止服务后放回同名目录。
- 删除照片关联不会物理清理上传文件，避免误删历史报告引用；长期使用需要补充孤立文件清理和保留策略。
- 本地 HTTP 不提供传输加密，只适合本机或可信局域网调试。正式业务部署需 HTTPS、独立账号、权限审计及备份策略。

## 多人检查与签名

检查人可输入多个姓名，用顿号或中英文逗号分隔，最多20人。同名人员请在姓名后加工号以区分。先填写完整名单，再在签名区选择当前检查人，分别手写并暂存签名。切换人员时会自动暂存当前签名，离开前仍需保存草稿。修改名单会清空原签名，必须重新签署。正式提交要求全部检查人签齐；报告和 Word 导出按姓名分别展示签名。原单人报告无需迁移，仍可查看。
