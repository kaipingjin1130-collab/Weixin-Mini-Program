# 小程序巡查派单与四阶段流程（本地候选版）

日期：2026-11-17。基于 `ce3e527`，保留 11 月 13 日的多人合并报告、手写 / 插入电子签名、照片格式转换和 Word 签名排版修正。

本次仅修改本地源码并上传 GitHub。没有部署服务器、写入线上业务数据、上传微信体验版或提交审核。

## 使用流程

1. 登录后进入“巡查任务工作台”。项目经理 / 管理员填写项目、工地、日期、需求人数、组长和邀请人员，发布任务。
2. 被邀请人员用本人账号接单。组长或项目经理从已接单人员中确认最终名单；实际选定人数与需求不符时必须说明原因。确认后名单锁定，进入现场检查。
3. 现场照片、隐患和记录先保存到草稿箱。检查完成后交组长筛选；组长可以退回补充，或勾选最终清单、说明排除理由。原始记录全部保留，报告只包含选中内容。空清单须明确无隐患并填写结论。
4. 生成报告后，由检查名单全员、组长及被检查人签字。原有多人会签和现场被检查人手写 / 图片签字继续可用。检查人和组长的必签位置不能从名单移除。全部指定位置签齐后，由组长 / 项目经理核对报告修订并确认发布。
5. 发布后报告和签字锁定，进入工作认定。组长 / 项目经理从最终名单选择实际人员，填写每人工时及依据。认定只允许一次；接单、检查完成、报告生成都不会提前计为已认定工作。

任务工作台展示四个主阶段：**工地信息填写 / 任务派发 → 现场检查 → 报告生成 → 工作认定**。草稿筛选和会签分别属于第二、第三阶段。

历史任务保留原始编号、快照、签字与办理方式，不把已签历史报告迁移为新流程。新入口不再直接创建绕过名单确认的临时检查。旧手机草稿仍可按旧路径恢复；新建离线草稿必须绑定已确认名单且正在检查的任务。

## 统计口径

- 本人统计：已接单、名单确认、报告发布、工作认定任务数，以及实际工时、去重工作日期。
- 全部人员：仅管理员可读；普通账号不能通过改查询参数读取全部人员统计。
- 项目用工：累计需求、确认和实际量以“人次”为单位；另外展示去重人数和单次最大需求。
- 合同核对：配置“合同每次要求人数”和合同条款依据，比较每个任务的需求人数，标出超过要求的任务。未配置与零人数是两种状态，不把未配置视为合规。
- 老平台统计：可单独读取 WM 的个人 / 全员核定结果，沿用 WM 的“人员、日期、合同”去重规则；不将其与小察按任务统计的数值直接相加。WM 的权限检查继续生效。
- 老平台最终参与人员在工作认定后同步为实际人员，避免缺席人员被误计入老平台工作量。

## 本地运行与微信开发者工具

执行 `start-mobile-local.cmd` 启动只监听 `127.0.0.1:18817` 的独立本地服务。数据保存到仓库 `.local/mobile-workflow-data`，不会复用云数据库或原有本地业务库；该启动文件明确清除继承的云数据库、老平台认证和消息发送配置。管理员初始密码由程序生成，位于该目录 `local-password.txt`。

在仓库根目录执行：

```powershell
python platform-module/tools/build_local_miniprogram.py --server http://127.0.0.1:18817 --output ../output/2026-11-17-mobile-workflow/miniprogram-local
```

将独立输出目录导入微信开发者工具。模拟器连接本机地址；真机测试需单独设置局域网监听和电脑 LAN 地址。未运行本地服务时不会连接正式后台。不要把该本地构建上传为微信线上版本。

新建项目、人员及角色可使用现有网页账号 / 项目管理入口。联调需分别用项目经理、组长、检查人和被检查人账号测试，不能用管理员代签检查人的签名。

## 老平台互通与微信提醒

已确认截图对应 `D:\integration\admin-web\src\features\tasks\TasksPanel.jsx`，接口对应 `D:\integration\wm\app\routers\tasks.py`。本次没有修改该目录的业务数据或启动旧服务。用于 WM 的两个接入文件和配置说明位于 [integrations/wm](integrations/wm/README.md)，同本次小程序源码一起提交。

互通调用真实 WM `/api/tasks` 和 `/api/workload` 接口，复用原任务创建幂等编号、修订检查、合同关联与权限。小察用事务出站队列保留待同步任务；网络失败保留错误及重试状态，不显示为成功。旧平台调整已经关联的任务时标记冲突，不覆盖任一端检查内容；需要负责人核对后处理。

站内派单、接单、名单确认、草稿筛选、签字、发布和认定提醒已实现。微信服务通知另外需要 AppID、AppSecret、已审核订阅模板字段及用户本人授权。绑定通过服务端交换 `wx.login` code 获取 openid，不接受客户端指定 openid，不保存 session_key。缺配置时页面明确提示，站内提醒仍可使用。

外部同步和微信发送由显式运行的 `tools/mobile_services.py` 办理，不会因启动本地网页或导入小程序自动向线上发出通知。发送结果不明的通知和成果标记为待核对，不盲目重发。订阅送达依赖微信侧授权次数与返回结果，不承诺必达。

测试涵盖名单权限、本人接单、修订冲突、响应丢失幂等重试、草稿保留、组长筛选、必签人员、未签齐拒绝发布、发布锁定、工作认定去重、合同人数与日期范围、订阅身份绑定和老平台真实 ASGI 路由。

原有合并报告 / 电子签名 / 图片导入 / Word 排版 / 离线同步回归继续运行。WXML 和 WXSS 使用本机微信开发者工具内置编译器检查。实际手机上的微信订阅消息送达和正式数据跨系统联调未执行，因为本次不发布或连接线上业务系统；这两项需要后续配置及真机验收。

新增表 `mobile_settings`、`mobile_notifications`、`mobile_outbox` 用于合同配置、提醒和出站队列。新任务和报告状态存入原 JSON payload，历史快照不改写。SQLite 随本地初始化建表；未来 PostgreSQL 环境须在备份后的迁移步骤显式执行新增表初始化，并进行数据库回归后再决定部署。
