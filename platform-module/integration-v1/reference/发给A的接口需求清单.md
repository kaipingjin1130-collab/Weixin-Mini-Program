## 二、接口1：当前用户身份与项目权限

**建议路径：** `POST /integration/v1/identity/resolve`

**用途：** B 查询当前用户身份、组织、可访问项目及业务权限。登录、会话验证和撤权规则全部由 A 实现，B 不建设账号或令牌签发系统。

**调用方式：** B 携带服务凭据及 A 代理转发的用户会话引用。请 A 明确请求头名称和格式；凭据与会话引用不得放在 URL 或日志中。A 代理须剥离浏览器伪造的内部身份头。

建议请求正文：

```json
{"project_id":"project-001"}
```

建议响应：

```json
{
  "active": true,
  "subject_id": "user-001",
  "display_name": "张三",
  "org_id": "org-001",
  "projects": [
    {
      "project_id": "project-001",
      "permissions": ["knowledge.read", "retrospective.read"]
    }
  ]
}
```

| 必需字段 | 要求 |
|---|---|
| `active` | 身份是否有效 |
| `subject_id` | 稳定用户标识，不用姓名或手机号代替关联主键 |
| `display_name` | 用户显示姓名 |
| `org_id` | 可信组织标识 |
| `projects[].project_id` | 用户当前可访问的项目 |
| `projects[].permissions` | 该项目的权限码；以上值为示例，双方需固定字典 |

需要明确：请求指定项目时是否仅返回该项目；无权限必须明确拒绝。无效/过期会话返回 401，服务凭据或权限不足返回 403。账号停用、退出、项目撤权后，后续请求须按约定失效。身份服务不可用时 B 拒绝受保护操作，不降级成管理员或模拟身份。

## 三、接口2：复用固定成果读取，新增资格元信息

**已有路径：** `GET /api/work/snapshot/{deliveryId}`。继续返回现有快照原始结构，不改为新外层，以免影响旧调用方。

**建议新增：** `GET /api/work/delivery-meta/{deliveryId}`。仅返回可变化的成果资格和归属元信息，与固定快照分开。

**用途：** B 获取指定成果的元信息及冻结快照，用于转换、接入和复盘。

**调用方式：** 使用有明确组织、项目及操作范围的 B 服务身份。后台处理不能依赖某个用户的会话始终在线；用户查看 B 结果时仍需校验当前用户权限。

新增元信息接口建议响应：

```json
{
  "source_system": "a",
  "org_id": "org-001",
  "project_id": "project-001",
  "task_id": "task-001",
  "delivery_id": "delivery-003",
  "delivery_version": 3,
  "eligible": true,
  "ineligible_reason": null,
  "withdrawn": false,
  "withdrawn_at": null,
  "withdraw_reason": null
}
```

快照继续通过现有 snapshot 接口读取，已有 schemaVersion、packageId、version、exportedAt、project、members、scenario、task、evidence、summary 等字段。请交完整实际样例和字段含义，B 负责映射，不要求 A 改写成 B 内部合同。

| 必需信息 | 具体内容 |
|---|---|
| 来源及归属 | 来源系统、组织、项目、任务、成果 ID、成果版本 |
| 可接入状态 | 是否符合接入条件、不符合原因、是否撤回及撤回信息 |
| 项目与场景 | 项目名称及合同信息，场景 ID、名称、版本和任务冻结配置 |
| 任务事实 | 编号、标题、对象、状态、实际业务时间 |
| 人员 | 账号标识、姓名及业务角色；手填办理人与实际代录账号分别记录 |
| 现场记录 | 稳定 ID、正文、发生及上传时间、作者、确认状态、证据 ID |
| 问题及处理 | 稳定问题 ID、描述、类别、部位、风险等级、期限、整改与复核历史、证据关联 |
| 过程事件 | 稳定事件 ID、动作、时间、操作者、关联对象和详情 |
| 交接归档 | 接收结果、归档事实及对应成果版本 |
| 附件清单 | 稳定文件 ID、名称、类型、大小、SHA-256 及来源关联 |

实现要求：

- 首轮仅接入归档时冻结的正式成果，历史归档版本仍按共同约定可追溯，资格由 A 后端判断；不能仅以报告目录里的 `submitted` 展示状态判断。
- 同一成果版本的快照内容固定，复用现有保存快照实现，不使用任务最新状态重新生成历史快照。资格和撤回状态可变化，放在独立元信息接口。
- 项目、任务、成果 ID 和版本之间必须可核对；B 不能借一个合法成果 ID 访问另一项目。
- 未知时间、人员等字段保持 null 或明确缺失；不以导出时间替代实际发生时间。
- 请说明补正、新版、历史版本和撤回的区别。补正不自动等于撤回旧成果。
- 当前未发现所需撤回实现，需要新增明确的状态维护与受权操作，元信息和取件检查同一状态。实现前不得默认 withdrawn=false 声称支持撤回；也不能用补正代替撤回。
- 旧报告导入会把日期拼成当天零点写入部分 occurredAt。请说明 sourceReportId/sourceReport/source 等来源标识和时间精度，B 将此类时间视为日期级信息；不要直接修改已冻结历史快照。

## 四、接口3：下载指定成果中的附件

**已有路径：** `GET /api/work/evidence/{id}`；元数据为 `GET /api/work/evidence-meta/{id}`。

**增量要求：** 对 B 服务调用建议增加必填 `deliveryId` 查询参数，如 `/api/work/evidence/{id}?deliveryId=...`，并核验附件属于该冻结成果；参数名由 A 固定后交 B。保留原用户调用兼容性，不要求另建一套附件服务。

**用途：** B 受控下载照片、文档等附件并校验内容。

已有接口返回文件流，需补充 B 服务身份认证。以下元数据已经存在于成果 evidence 清单或 evidence-meta 响应中，交付准确样例即可，无需重新实现：

```json
{
  "id": "evidence-001",
  "name": "现场照片.jpg",
  "mime": "image/jpeg",
  "size": 123456,
  "sha256": "实际文件内容的64位十六进制SHA-256摘要"
}
```

实现要求：

- 返回正确的 `Content-Type`；声明大小时与实际内容一致。
- 校验服务身份、项目范围、成果状态及附件确属该成果版本。
- 无权限、文件不存在、成果撤回分别明确返回错误，不返回登录网页冒充文件。
- 不提供任意磁盘路径或任意 URL 读取接口；B 不需要 A 本机路径。
- 请提供可接受文件大小、超时及服务凭据失效后的处理约定。

## 六、交付顺序与通过标准

1. **先交接口约定和样例**：双方核对后锁定 v1；B 即可用本地模拟 A 服务开发。
2. **再交真实接口**：A 验证实现与固定 Schema/样例一致；破坏性变更升版本并通知 B。
3. **最后连接验收**：B 替换基址和私有凭据，实际读取身份、成果与附件。

最低通过标准：同一用户在 A 登录后，B 能取得其当前权限，读取一份指定归档成果及照片，核对哈希；重复读取快照稳定，跨项目、失效身份、无权附件和撤回成果均被正确限制。

本清单只要求 A 提供自身能力和接口；A 无需修改 B 的 auth.py、任务包转换、队列、知识或复盘代码。
