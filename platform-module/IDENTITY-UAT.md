# 微信开发者工具：本机真实账号验收

仅用于单台电脑的开发者工具。无需新域名，不修改原演示工程或正式后台。

1. 请原平台管理员提供**获准用于验收**的私有认证入口及专用服务密钥，通过受控方式在启动进程环境中配置 `QAXC_UAT_AUTH_URL`、`QAXC_UAT_AUTH_KEY`，不要写入源码或小程序，也不要发到聊天。入口须实现既有 `login` 和 `identity` 协议，不是网页登录页。须确认该认证实例或验收副本不会写入正式库（包括登录审计）。HTTP 仅允许受控的本机回环入口或隧道；否则须用 HTTPS。
2. 在本目录执行 `python tools/start_identity_uat.py`。只监听 `127.0.0.1:18818`，SQLite 和附件使用仓库忽略的 `.local/identity-uat`。没有验收专用配置时拒绝启动。不要启动外部平台同步或微信推送 worker。
3. 生成客户端：`python tools/build_local_miniprogram.py --identity-uat --server http://127.0.0.1:18818 --output <新的空目录>`。在开发者工具导入该目录，确认登录页有“本机验收”标记。不要上传该工程。各验收人员分别输入本人的原平台账号；每次换人先退出登录，不交换密码或签名。
4. 通过已授权临时通道启动时，使用 `run_identity_acceptance.py` 开启严格项目权限同步。登录只登记经原平台核验的稳定用户 ID；项目授权来自原平台 A 模块 `a.memberships`，不从姓名、手机号或登录行为推断权限。仅镜像项目 ID、名称及有效真实账号的成员角色，不复制正式任务、合同、签名或密码。无成员记录的账号可登录但无项目权限；本机页面不能自行新增或提升成员权限。
5. 按真实角色验收：经理发布巡查任务并指定组长；项目内具备巡查权限的人员自主报名接单，项目负责人移除不合适的报名人员并确认最终名单；完成现场记录后点清单上报、核对、提交，组长筛选；各必签人逐一核对并本人签字（含被检查方），检查未签齐不能发布。测试签字只用于标明“验收”的本机任务。记录项目、任务编号、操作角色、预期与实际结果，不记录密码或签名图片。

真实身份、项目授权和签字均需在现场核验；本地自动化回归不能代替该验收。不因验收成功自动部署线上。

## 已授权的临时认证通道

2026-11-18 配置了一条四小时有效的认证通道。正式 Python 业务服务不重启、不更改数据库连接；新工作流仅在本机 `127.0.0.1:18818` 运行。原平台既有认证适配器校验账号；适配器的原始服务密钥只留在云端进程中。业务 SQLite、附件和待同步队列均留在本机，不启动对外同步或推送 worker。

`uat_identity_gateway.py` 接受原平台有效账号的 `login`/`identity` 请求，拒绝 session 复用和其他接口，返回的身份不授予系统管理员。账号须由原平台认证接口确认为 active、aud=qaxc，且具有合法稳定 `host:admin:N` ID。单独的 SSH 公钥使用 `restrict`、到期时间和固定命令，只能把有长度限制的请求转给云端回环认证代理；不允许 Shell、PTY、agent 或端口转发。

`install_uat_channel.py` 通过已登录云终端安装短期代理及 systemd 撤销定时器；输入包中的临时令牌和公钥不属于源码。云端临时目录固定为 `/opt/qaxc-identity-uat-20261118`。自动到期后删除对应公钥行、停止临时代理并删除临时文件；不改其他 SSH 密钥或正式服务。提前撤销可在云终端运行 `sudo systemctl start qaxc-identity-uat-expiry.service`，随后确认代理停止和对应公钥行已移除。

本机使用 `python tools/run_identity_acceptance.py`，从仓库忽略的 `.local/identity-uat-channel/config.json` 读取临时令牌及到期时间，使用同目录独立 SSH 密钥和已核对指纹的 `known_hosts`。启动器只继承必要操作系统路径，其中 Windows OpenSSH 需要 `ProgramData`；不继承正式数据库、同步系统或推送密钥。到期后自动关闭本机两个服务。不要重复启动已有运行实例。

`seed_identity_acceptance.py` 只初始化尚不存在的本机数据库，使用同目录私有 `project.json` 中只读核验过的稳定用户 ID、项目 ID 和角色，不从姓名推断权限、不导入正式任务或合同。人员快照、凭据、数据库、测试签字和日志都不提交 Git。

首次配置已验证错误服务令牌 403、session 路由 404、任意 SSH 转发拒绝和未登录工作接口 401。本次扩展后实际核对第三个原平台账号身份读取 200，其源角色 viewer 原样保留，未提升为经理或检查员；session 和任意查询路由仍为 404。原平台账号的真实密码登录及本人签字需由用户完成。程序回归与测试图片签字不代表真实验收通过。正式上线仍需验收后的单独操作。

## 2026-11-18：按原平台项目权限扩展人员

- 临时代理在原服务 Python 环境中运行固定 SELECT，只投影 `a.projects.id/name` 和 `a.memberships.user_id/role`。连接和事务均强制只读，设置查询超时与结果大小上限；没有通用 SQL 接口、业务写入、正式服务重启或密钥外传。每个成员还需通过原平台 identity 校验，停用账号不进入人员名单。
- 登录和每次已登录请求均重新核验身份、获取权限快照。本机 `uat_permissions.py` 只允许专用路径的 SQLite，拒绝 PostgreSQL 和其他目录；权限查询失败、缺失、过期或角色异常时拒绝本次访问，不能沿用旧权限。同步替换成员授权，保留本机任务、报告及签字；并发旧快照不能覆盖新快照。
- 原平台 manager 可派单；manager/inspector 在该项目巡查任务发布后均可自主报名接单，无需邀请。viewer 不能派单、接单或写入任务；其他业务角色仍受既有工作流限制。没有源项目成员记录的其他用户不自动获得权限，也不能跨项目办理。
- 已有明确授权的本机经理测试例外记录在忽略目录 `role-overrides.jsonl`，不提交 Git，不改正式角色。例外仅在同一项目、同一稳定 ID 的原始成员角色仍存在且未改变时应用；原平台撤销成员或改变角色后不继续提权。新增用户不会生成此例外。
- `upgrade_uat_channel.py` 仅替换并重启现有临时代理，核验权限读取、原业务服务 PID 未变及撤销定时器仍有效；失败恢复原代理文件。既有 SSH 限制、令牌、到期时间不变，不延长验收授权。正式库未做迁移或写入。
- 本次实际镜像 2 个源项目、4 条成员关系（3 个有效真实账号）；没有原平台项目权限的其他账号仍需由原平台管理员另行配置，本次不会代改正式库。没有把演示本地账号映射为真实人员。

## 自主报名与最终名单

- 新流程任务发布即开放报名，通知项目内所有 manager/inspector。报名人数可以超过需求人数，报名不等于最终入选；无项目权限、停用账号及只读角色仍不能报名，不因报名自动授予项目权限。
- 项目负责人（manager，或系统管理员）可以在名单确认前使用“移除报名”，并勾选最终检查人员。检查员即使被指定为组长，也不能代替项目负责人移除报名或确认名单；组长的后续草稿筛选权限保留。
- 移除只作用于本次任务的报名，不删除账号或项目成员。保留操作人、时间和原因；被移除者不能重复报名该任务。接口重试也不能恢复被移除的报名。
- 确认最终名单后停止报名和移除，名单锁定。只有入选人员可以现场录入；后续清单上报、签字和发布流程不变。报名、移除和确认均校验任务版本，避免并发操作覆盖名单。
- 已有尚处于派单阶段的新流程任务同样开放自主报名。已确认或已签字任务不回退、不改内容，无数据库迁移。本次仅更新本机验收服务和客户端，正式库不动。
