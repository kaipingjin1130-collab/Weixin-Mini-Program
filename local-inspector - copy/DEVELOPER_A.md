# 开发者 A 操作说明

本版本实现作业协同与成果主流程，并将现场作业与后续管理分到两个客户端。小程序产出现场记录和简报，网页平台接收这些事实后办理整改、正式报告、交接和归档。两端共用业务后台，开发者 B 维护的知识与复盘系统仍然独立。

## 计划巡查与临时巡查

现场端支持两种入口：执行平台派发任务，或点击“＋ 发起临时巡查”自主开始。自主巡查只允许选择当前账号具有检查人／项目负责人权限的项目；系统管理员也可发起。仅有整改、复核、接收角色的账号不能自行建立现场巡查，更不能操作未授权项目。

自主发起时选择项目及检查场景，填写名称、检查对象、预计完成日期和场景字段。系统自动把登录人设为执行人，生成稳定编号并记录来源和发起人；确认准备清单后即可采集，不等待平台派单，也不要求提前配置成果接收人。未上报前任务同样可在平台查看，但必须上报后才能由平台接收材料。

上报后沿用原闭环：平台负责人接收材料时手动填写“最终成果接收人”姓名，然后分派整改、复核销项、生成正式报告和交接归档。平台退回补充时不必先指定接收人。两端分别显示“平台派发”或“自主临时巡查”，历史任务未保存来源时按平台派发显示。

## 运行与登录

1. 双击 `start-lan.cmd`，保持后台运行；仅电脑使用时可运行 `start-local.cmd`。
2. 本机浏览器访问 `http://127.0.0.1:8765/work`，用 `admin` 与原本地密码登录。
3. 手机和电脑连接同一可信 Wi-Fi。小程序登录页填写 `http://电脑当前IPv4:8765`，输入自己的账号与密码。
4. 更新小程序源码后，在微信开发者工具重新编译并重新真机调试。只刷新网页不会更新手机的小程序代码。
5. 小程序的录音需要实际 AppID 对应的隐私声明、麦克风授权及真机验证。不能以接口模拟测试代替真实设备验证。

当前为本地可运行原型。公网生产部署还需要 HTTPS、合法域名、生产会话与账户管理、备份运维等配套工作。不要把这套本地 HTTP 开发服务直接映射到公网。

## 两端职责

| 业务 | 小程序现场端 | 网页平台 |
| --- | --- | --- |
| 项目、对象、任务 | 查看派发任务；在有检查权限的项目自主发起临时巡查 | 建立项目与计划任务；接收自主巡查 |
| 成员与分工 | 使用分配的成员账号 | 创建账号，分配项目角色及执行人 |
| 现场作业 | 检查准备清单、拍照录音、记录发生时间 | 查阅记录及证据 |
| 记录确认 | 保存草稿、人工确认，确认记录不可直接覆盖 | 接收上报或退回补充，不代改现场原文 |
| 现场发现的问题 | 登记描述、人工风险等级及证据 | 指定整改人、复核人和期限 |
| 现场简报 | 生成并查看、预览／分享 Word、上报 | 查阅每个上报版本，接收／退回 |
| 整改闭环 | 查看处理进度 | 回复、上传整改证据、复核、退回、销项 |
| 正式成果 | 不提供正式成果办理入口 | 正式报告、交接摘要、接收、归档 |
| 补正 | 收到退回后追加确认记录，再上报 | 退回材料或对已归档任务发起有原因的补正 |
| 交给 B | 不承担跨系统传输 | 导出指定成果版本的 JSON／ZIP 包 |

小程序从界面上收拢到现场操作；后台安全边界按账号和项目角色控制，不依赖客户端“自报来自手机或网页”。具有项目负责人权限的账号在 API 层具备相应管理能力。

## 首次配置

在网页平台展开“账号与项目管理”，建立项目和个人账号。随后选择项目，使用已有登录账号添加成员：

| 角色 | 权限 |
| --- | --- |
| 系统管理员 `admin` | 创建账号、项目、发布场景配置、维护项目分工；不能冒充指定整改人、复核人或成果接收人操作 |
| 项目负责人 `manager` | 管理本项目成员与任务、接收现场材料、分派问题、生成成果、归档和发起补正 |
| 检查人 `inspector` | 本项目现场记录、草稿确认、发现问题；由任务指定执行人汇总上报 |
| 整改人 `rectifier` | 对指定给自己的问题回复整改并提交证据 |
| 复核人 `reviewer` | 对指定给自己的问题复核销项或退回 |
| 接收人 `receiver` | 对指定给自己的任务成果确认接收或退回 |

每个账号在一个项目内有一个角色；同一账号在不同项目可有不同角色。项目负责人可被指定为执行人、整改人、复核人或接收人，但默认场景禁止同一人兼任某个问题的整改人与复核人。演示时建议使用五个独立成员账号来验证角色边界。

## 完整演示流程

1. **网页建立任务**：选择“质量安全巡查”或“设备交接验收”，填写对象、场景字段、完成期限、执行人和成果接收人。上传任务资料后可关联到任务，现场端能够查看。
2. **手机现场执行**：进入现场任务，逐项确认准备清单，开始执行。拍照或录音，填写记录的实际发生时间及正文，关联证据，保存草稿或确认。
3. **手机登记问题**：输入问题现象及部位、选择风险等级并关联照片等证据。新问题为“待分派”；默认临时期限由场景设置生成，平台分派时确定正式期限。
4. **手机生成简报上报**：全部草稿确认后，由指定执行人填写现场摘要并上报。服务端保存一个不可变的现场简报快照，可以在手机查看及预览 Word。简报明确标注“非正式审核报告”。
5. **网页接收材料**：项目负责人查阅简报、记录及证据。接收后，整改办理入口开放；若退回，必须填写补充内容，手机刷新可见。
6. **网页整改与复核**：负责人为问题指定整改人、复核人及期限；整改人登录，上传并勾选证据后提交整改说明；复核人登录，核对后销项或退回。默认要求整改回复有证据。
7. **网页正式报告**：全部问题销项、记录确认且现场材料已接收后，负责人填写交接摘要并生成成果。可下载 Word、浏览 HTML 报告、打印为 PDF、导出问题清单 CSV。
8. **网页交接归档**：手填接收人姓名的任务由平台负责人登记成果接收结果，记录实际操作账号；历史绑定账号的任务仍由指定接收人确认。负责人再归档。归档生成包含接收意见和归档事件的最终成果版本。初次交接版本保持不变。
9. **导出给 B**：从成果版本处下载 ZIP。内含 `task.json`、可离线查看的 `report.html` 和实际证据文件。B 不需要读取 A 数据库。

平台退回现场材料时，已经确认的原始记录不直接修改，而是新增补充记录，再生成新版简报。已归档任务不能直接编辑；负责人可填写原因发起补正，重新经过现场上报、平台接收和交接归档。历史简报和成果快照均保留。

## 数据互通与一致性

- 两端共享 `tasks`、`evidence`、`field_reports` 和 `deliveries` 等数据库表；刷新读取同一事实，网络请求失败会明确报错。
- `taskId`、记录 ID、问题 ID、对象 ID、证据 ID 为稳定 UUID；任务另有便于阅读的编号。
- 记录区分 `occurredAt` 实际发生时间与 `uploadedAt` 上传时间；发生时间需要带时区。
- 更新任务必须带当前 `revision`；过期修改返回 HTTP 409，阻止多人互相覆盖。
- 写接口支持 `requestId` 去重。同一请求编号配不同内容会被拒绝。客户端每次新操作生成新编号；未实现自动离线同步队列。
- 上报、整改、复核、接收、归档及补正记录操作者和服务端时间。历史快照使用固定场景配置和成果版本。
- 成员只能读取所属项目的任务、旧报告及证据。没有项目权限时，即使知道证据或导出地址也不能访问。
- 服务重启后需重新登录；共享管理员原密码保持不变。

## 扩展与知识服务

网页“场景配置与扩展”支持 JSON 发布：项目类型、任务字段、准备清单、记录类型、角色集合、整改证据要求、人员分离规则、默认期限、报告标题及 HTML 报告章节。提供两个场景验证这些配置。发布使用版本校验，旧任务保留创建时的配置。

本版使用固定业务节点，不是通用流程设计器；新增任意流转节点仍需开发。角色集合目前固定为五种业务角色。记录类型可配置，但每类记录仍统一使用正文、发生时间和证据结构，未做任意记录字段表单设计器。Word 使用统一排版，HTML 报告支持配置章节。

知识查询在未配置 B 服务时使用演示知识包，明确标注非规范条文；外部服务不可用也不阻塞业务。识别适配器未配置时提示人工整理，绝不伪装成已经完成语音转写或图像识别。

## 本次实现的边界

已实现本地任务主流程、角色与项目隔离、录音文件采集入口、现场简报、整改复核、正式报告与交接归档、版本冻结、接口样例及回归测试。

仍需联调或后续建设：

- 真实语音转写／OCR／视觉识别供应商；当前只提供统一适配接口和人工确认回退。
- 微信真机的麦克风授权、实际录音上传、Word 预览，以及不同手机的相机与文件行为。
- 微信统一身份登录、企业 SSO、B 系统身份校验实际联调；当前为 A 内部账号及会话。
- 生产账户生命周期（禁用、密码找回、重置）、TLS、部署运维、自动备份与容量治理。
- 系统提醒当前为页面待办和逾期提示，没有短信、微信订阅消息或后台推送。
- PDF 通过浏览器打印生成，未提供服务器自动 PDF 转换。
- 独立外部“巡查平台”若另有厂商系统，仍需其接口文档；本次实现的是本项目自有网页平台，不等同于已接通外部厂商平台。
- 当前草稿保存在服务端，未提供断网拍摄后自动补传功能。

## 文件与备份

现有 `data/inspections.sqlite3`、`data/uploads/` 与本地密码继续使用。数据库升级只增加业务表，不清空原报告。旧巡查工作台仍在网页 `/`，同项目已提交报告可导入新任务，自动生成确认记录和待分派问题，避免重复录入。

更新服务前建议用 SQLite 的备份接口备份数据库；完整备份还应包含 `data/uploads`。当前任务处理和导出均在本机完成；仅在管理员明确配置知识／识别服务后，相应查询或识别文件会发送到配置的服务。
