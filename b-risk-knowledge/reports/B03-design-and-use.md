# B03｜质量核查与知识加工（模拟版）

日期：2026-10-20。本次包含用户要求的历史数据治理导航与报告视图调整，并执行下一任务B03。继续使用模拟数据和本地结构化模拟生成适配器，没有接入真实模型或外发资料。

## 已确认的产品用语

- 左侧“历史数据治理”为点击展开/收起的分组，子项为“数据来源”“历史项目”“风险数据”。
- “历史项目”就是原“接入批次”的页面概念，仍复用`/imports`、批次ID和处理结果。一批导入保留一个历史项目条目，本轮不另造项目主数据。
- “风险数据”复用`/records`，默认“报告清单”；点击报告展开其风险数据，可继续打开原始字段、生效值、版本和证据。可切换“逐条数据”，保留现有筛选和分页。
- 报告按来源命名空间下的报告身份组织，不因报告名相同自动合并跨项目或跨来源资料。展开记录的授权和分页都由后端校验。
- 当前风险数据字段保持模拟结构。后续按用户提供的真实数据核对映射、字段显示和新版本，不预先把模拟39列当成最终字段合同。

## 直接试用

沿用根目录“启动B模块.cmd”。风险数据入口：<http://127.0.0.1:5181/records>；B03入口：<http://127.0.0.1:5181/quality>。

1. 点“历史数据治理”体验展开/收起，再进入“历史项目”“风险数据”。报告清单会展示4个来源报告分组，点机场CSV报告可展开6条数据；筛选条件同时作用于报告清单和展开记录。
2. 打开“知识加工与审核→质量核查”。日期异常、坏图片字段和后备身份由规则检查形成。点击分类可筛选对应问题，处理时填写理由，人工补充独立保存，不覆盖原始值或治理生效值。
3. 切换“知识候选”，选同一项目的明确来源版本和卡片类型，先预览范围，再确认生成。项目、日期、描述、已有治理值和证据引用自动带入。
4. 模拟生成支持案例卡与检查要点卡。单项失败单独显示，其他项保留。再次生成相同来源版本/类型/模板会复用已有卡片，不覆盖草稿、人工修改或审核内容。
5. 打开知识卡，左边看固定来源和证据，右边编辑结构化内容。未保存修改及历史版本均显示具体字段的原/新值。保存创建新草稿版本，提交审核只针对当前已保存版本。
6. 审核员填写意见并明确勾选已核对事实证据，再批准此版本；也可退回、修改和重新提交。审核后依然“未发布”，发布与检索由B04实现。
7. 可在生成区展开“模拟校验场景”，验证错误证据ID和待核验依据。错误引用拒绝保存；系统补充依据只能“待核验”或明确“不采用”，本版不提供伪造“已核验标准”的开关。

本次演示库保留3张模拟知识卡：一张草稿案例卡、一张经过退回修订并审核的案例卡、一张待审检查要点卡。浏览器验证产生的意见明确写有“模拟”。

## 模块、表和接口

| 文件/模块 | 职责 |
|---|---|
| `backend/modules/knowledge/quality.py` | 规则问题同步及初始化补齐；同来源版本同规则不重复，已处理状态不重置 |
| `adapter.py` | 独立生成适配入口；当前只有`local-structured-mock-v1`，无外部调用 |
| `schemas.py` / `scene-packs/generic/` | 结构化卡片校验、版本化JSON Schema和模板配置 |
| `service.py` | 来源授权、证据引用、不可用来源阻断、版本比较、审核状态转换 |
| `tasks.py` | 复用Procrastinate逐项生成，生成签名锁和持久化单项结果 |
| `api.py` | 质量、生成、知识草稿与审核API |
| `frontend/src/Knowledge.tsx` | 质量问题、批量范围预览、卡片编辑、修改差异和审核界面 |

迁移`0003_b03_knowledge`新增任务书的6张表，加逐项生成账本`generation_entries`：

| 表 | 核心约束 |
|---|---|
| `quality_issues` | 来源版本+规则码唯一；状态和row_version并发控制 |
| `record_annotations` | 补充内容、来源类别、操作者、理由和对应来源版本独立保留 |
| `knowledge_items` | 来源版本+知识类型+模板唯一；当前修订和对象row_version |
| `knowledge_revisions` | 卡片+版本唯一；内容、Schema/模板/模型标识、状态和版本 |
| `knowledge_evidence_links` | 精确到`/facts/n/text`的证据引用；不只关联整卡 |
| `review_actions` | 卡片、修订ID、准确版本、审核人、动作、理由、时间 |
| `generation_entries` | 任务+来源版本唯一；新增/复用/失败逐项可核对 |

主要接口前缀`/api/v1`：

| 接口 | 含义 |
|---|---|
| `GET /reports`、`GET /records?document_id=` | 报告分组、展开风险数据；沿用项目/来源/类型/质量/日期筛选 |
| `GET /quality/issues`、`PATCH /quality/issues/{id}` | 分类、状态、处理说明、人工补充 |
| `GET /knowledge/source-options`、`POST /knowledge/generation-preview` | 明确可选范围、授权版本与生成前预览 |
| `POST /knowledge/generation-jobs`、`GET /knowledge/generation-jobs/{id}` | 异步生成202及单项结果；要求幂等键 |
| `GET /knowledge`、`GET /knowledge/{id}`、`GET /knowledge/schema` | 候选、固定来源、修订历史和结构 |
| `PATCH /knowledge/{id}/draft` | 携带revision_id/row_version/content/reason，新建修订 |
| `POST /knowledge/{id}/submit-review` | 提交当前已保存版本 |
| `GET /reviews`、`POST /reviews/{id}/approve`、`POST /reviews/{id}/request-changes` | review id就是被审核修订的UUID，有稳定映射 |

批准须同时携带当前修订ID、row_version、审核理由和`evidence_checked=true`。版本过期409。内容变更后创建新草稿，旧批准不能用于新内容。

## 权限与事实边界

加工员/管理员可处理质量问题和编辑候选，审核员/管理员可审核。所有操作叠加来源项目授权；学员不能读取尚未发布的加工区，包括已审核但未发布的卡片。B04以后另提供按发布及权限控制的使用入口。

引用只能指向本次授权来源版本的证据。批准事实必须包含本版本锚定的来源行；候选图片不能单独证明事实。来源撤回后，卡片读取及新生成阻断；来源当前版本变化后，旧版本卡片不能继续提交或批准。

“来源生效值”“人工补充”“模拟建议”分别标识。人工更改事实文本时由服务端标为人工补充。质量问题处理只记录说明，不自动把未知日期补成某天，也不消除原始导入警示。标准名称、条款、版本、来源和核验状态分开；待核验标准不得批准为有效依据。
