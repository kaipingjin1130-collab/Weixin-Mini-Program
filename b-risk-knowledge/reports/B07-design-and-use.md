# B07 培训与学习记录、施工要点知识萃取

日期：2026-10-22。沿用现有 B01–B06 项目、数据库、队列、证据与审核，没有另建 LMS 或第二套审批。培训使用现有模拟知识和 B06 复盘经验；新增云端兼容接口可调用大模型自主加工知识。当前未提供真实模型密钥，实际云端归纳效果尚未验收。

## 用户现在怎么用

双击根目录 `启动B模块.cmd`。服务地址、账户范围沿用原本地工程，真实身份和生产多人部署仍待 A 联调。

1. 管理员进入 [云端模型配置](http://127.0.0.1:5181/settings/models)，填写服务地址、模型名称、密钥，勾选启用，保存后测试连接。服务须支持 Chat Completions 兼容协议及 JSON 输出。密钥在本机填写，不要发到聊天或提交 GitHub。
2. 进入 [施工要点萃取](http://127.0.0.1:5181/extraction)。配置类别名称、编码、施工关注点和可选关键词，保存分类版本；后续用户提供正式类别时直接增改这些行。
3. 勾选已有风险记录，选择“调用云端大模型，自主分类与提炼”，提交后台任务。模型完成跨记录分类、合并、去重和要点归纳；不要求逐条手工改写。
4. 打开候选，核对类别、施工准备/现场实施/验收复核中的施工要点、检查方法、常见问题和证据摘录。来源归纳和新增建议分别标识。人工可修改，保存为新版本，再走原知识审核和 B04 发布。
5. 教员进入 [培训题库](http://127.0.0.1:5181/training/questions)，选择已发布知识版本生成候选，核对题面、答案和评分要点后提交统一审核。题库可筛选已用于发布学习包的题目。
6. 在 [学习包](http://127.0.0.1:5181/training/packages) 选择已审核题目，建立固定版本并发布。学员切换右上角“新成员”，进入 [我的学习](http://127.0.0.1:5181/learn) 开始、保存并提交作答。
7. 教员进入 [学习结果](http://127.0.0.1:5181/training/results) 核对案例问答的建议分，填写确认分和原因。原建议分、评分规则、模型名称与人工复核流水保留。

现有演示包为“新人风险识别与B06复盘练习（模拟）”v1，共5题：来自 B06 经验的单选、多选、案例问答，以及原模拟风险知识的单选、案例问答。准备脚本 `tools/prepare_b07_demo.py` 通过真实本机 API 流程创建，审核理由明确标注模拟验收；不读取原始报告，不调用外部模型，不覆盖手改版本。

## “自主知识加工”的实际范围

旧 B03 本地适配器只复制描述并加固定建议，不能当作有效知识总结。本轮增加独立的“分类—归纳—校验—候选”加工入口，并保留旧入口兼容原流程。

- 用户选择一组固定风险记录和分类版本，模型按类别自行归并，不逐条产生同义改写。
- 每卡包括类别、事实摘要、施工要点、阶段、检查方法、常见问题、来源归纳/建议属性、原文摘录及证据ID。
- 同一类别每批最多一张卡；模型不能自行添加未配置类别。信息不足放入资料缺口，不补造整改结论或标准条款。
- JSON结构由 Pydantic 验证；来源ID须属于本批固定范围，原文摘录须确实存在。伪造引用、伪造摘录、未知类别、截断输出均拒绝保存，不自动发布。
- 原文匹配证明可定位，不等于语义蕴含、工程正确性或建议安全性；后两者仍由审核与后续独立评测验证。
- 模型只接收所选生效字段，不上传整份原报告或照片。当前没有图片识患、OCR或长文档自主遍历。
- 未配置/接口失败不会自动退回模板。用户必须明确选择“本地模板演示”才能得到模板结果，界面和任务均显示该模式。

目前单次20条来源、60000字符、输出最多10类卡片。超过范围明确拒绝，不静默截断。长文档与更大批次可后续接分块/多轮归纳；仍应复用现有队列。

## 页面与角色

| 页面 | 实际功能 |
|---|---|
| `/extraction` | 分类版本、来源选择、云端/显式模板加工、后台结果与候选入口 |
| `/settings/models` | 管理员配置、密钥只写本机、无业务文本连接测试 |
| `/knowledge/{id}/edit` | 原知识加工页增加施工要点编辑、跨记录固定来源与摘录 |
| `/training/questions`、`/{id}` | 三题型、筛选、修订、统一审核；管理响应带答案 |
| `/training/packages` | 固定题目版本、题序、角色范围、学习包发布 |
| `/learn`、`/learn/attempts/{id}` | 可用包、本人作答保存与提交、提交后结果与反馈 |
| `/training/results`、`/{attempt_id}` | 范围内完成情况、错项、建议/确认分及复核原因 |

新增模拟“培训教员”身份，仅机场项目；初始化只补缺失用户，不恢复撤销角色。教员/管理员管理培训，教员/审核员/管理员审核题目。学员仅访问自己的学习记录；教员看结果需本项目教学权限，不能用普通学员接口访问他人记录。

## 数据库和兼容设计

迁移 `0007_b07_training_extraction.py` 新增10表，保留原数据：

| 表 | 用途与主要约束 |
|---|---|
| `knowledge_taxonomy_revisions` | 项目+版本唯一，分类不可原地改写 |
| `knowledge_source_versions` | 卡片+来源版本唯一，支撑跨记录事实、引用和撤回 |
| `knowledge_extraction_runs` | 原后台任务外键、固定分类/来源/模型配置指纹、提示词版本与结果；不含密钥 |
| `training_questions` | 项目、题型、场景、当前版本；来源+题型+模板指纹去重 |
| `question_revisions` | 题面、选项、答案、rubric、固定知识版本、状态和评分规则；题目+版本唯一 |
| `learning_packages` | 包组+版本唯一、项目、角色范围、发布状态 |
| `learning_package_items` | 包版本+位置唯一、包版本+题目版本唯一 |
| `training_attempts` | 学员、固定包版本、状态、开始/提交时间；学员+开始幂等键唯一 |
| `training_answers` | 练习+题目版本唯一；原作答、建议分、确认分、解释、规则/模型与并发版本 |
| `training_score_reviews` | 每次人工评分前值/后值、教员、原因和时间，不能用可变总分替代 |

原 `review_actions` 增加 `question_revision` 类型，继续通过 `/reviews/{revision_id}/approve` 与 `/request-changes` 分发到领域校验。无独立审批系统。

知识卡扩展可选类别和 `construction_points`，旧卡兼容。跨来源关系仍有真实外键，不伪造风险记录。B04发布/两通道检索在排名前过滤任一失效来源；引用按实际来源版本定位。来源归纳型施工要点可索引，新增建议不冒充来源事实。

新队列类型 `knowledge_extraction`、`training_grading` 复用 B01 同事务入队和恢复机制。云端模型等待不阻塞作答提交；评分请求前后重新授权并核对来源，迟到结果不能覆盖人工确认分。失败重试保留已完成分项，评分重试可固定当前配置处理剩余项。

## API（内部 `/api/v1`）

| 接口 | 关键行为 |
|---|---|
| `GET/PUT /models/settings`、`POST /models/test` | 管理员；写入本机 `.local/model.json`，不回传密钥；连接测试只发送测试文本 |
| `GET/POST /knowledge/taxonomies` | 固定项目分类；保存带 `expected_version`，并发冲突409 |
| `POST /knowledge/extraction-jobs`、`GET /{id}` | 选择固定来源、分类版本、mode；要求提交幂等键；队列执行，结果只有草稿 |
| `POST /training/questions/generate`、`GET /training/questions`、`GET /{id}` | 已授权、曾启用发布的审核知识版本；当前使用明确本地出题模板 |
| `PATCH /training/questions/{id}/draft`、`POST /{id}/submit-review` | 新版本及并发校验；原审核接口审批 |
| `POST/GET /training/packages`、`GET /{id}`、`POST /{id}/publish` | 当前审核题目组包，发布后固定题目版本 |
| `POST/GET /training/attempts`、`GET /{id}` | 开始要求幂等键；学员 GET 只返回专用题面Schema和本人保存值，无参考答案/rubric |
| `PUT /training/attempts/{id}/answers/{question_id}` | 保存幂等、并发版本校验；提交后409锁定 |
| `POST /training/attempts/{id}/submit`、`GET /{id}/result` | 重复提交同结果；提交后才显示答案及解释 |
| `GET /training/results`、`POST /training/answers/{id}/review-score` | 项目教员/管理员；评分原因、分项版本与原建议保留 |
| `POST /training/attempts/{id}/feedback` | 本人提交后的评价与说明 |

详细请求结构以运行中 `/docs` 为准。A/B原B00机器合同没有修改，真实服务身份仍未联调。

## 评分与撤回

客观题按正确选项集合完全一致得100分，否则0分，不做模糊部分分。案例问答默认按教员可编辑的关键词要点给建议分，不能判断工程正确性；可选云端建议评分，异步执行，仍须教员确认。模型未配置/失败时保留作答，分数为null、状态待评分；不能填0分冒充完成。任一题未确认时确认总分为null。

题目修改只产生新版本，旧包和历史分数不改写。B06撤回经原知识来源保护传导到训练：停止新练习；历史结果保留数值，题面、参考答案、原作答、rubric与反馈正文全部隐藏。新B05撤回通知记录B06/B07实时来源保护已生效，历史pending通知未批量重写；在线保护不依赖通知补扫。
