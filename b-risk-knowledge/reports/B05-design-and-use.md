# B05｜A任务包接入与版本管理

日期：2026-10-21。当前为**模拟资料、本地mock服务身份和受控模拟取件连接器**的本地实现。接收、队列、数据库、文件校验和页面实际运行；未连接真实A系统，没有生成复盘或培训内容。

## 直接试用

1. Docker Desktop开启后，双击根目录“启动B模块.cmd”。打开 <http://127.0.0.1:5181/task-packages>，选择本地管理员或资料加工员。
2. 点击“导入模拟任务包”，默认载入完整作业过程。点击“预检查”，确认人数、事件、问题和附件数量，再点击“确认导入”。不用重复录入任务、人员、隐患、整改和复核资料。
3. 完成后查看任务快照、8个事件、2个附件，以及“最新接收版本/当前可用版本”。可以从事件直接打开对应证据，也可在附件区预览示意图和文字记录。
4. 再次导入相同内容复用原接收记录。在同一演示任务组选择“相同任务的第2版”，接入后自动切换当前版本；仍可打开第1版，展开查看具体整改、复核说明和来源顺序变化。
5. 其他场景分别演示缺实际时间、未知事件、附件校验失败、取件标识失效、只有资料无事件、中断后重试。各异常场景使用独立模拟任务，避免与完整包的第1版冲突。可点击“换一组新的模拟任务”。
6. “中断后重试”场景失败后，点击“重试接入”；已提交事件和附件关系不会重复新增。
7. 管理员或审核员填写原因撤回包，正文、事件、问题和附件停止在线使用。撤回当前包后不会自动恢复旧版。下游失效通知显示待处理，B06/B07尚未实现。

可以选择本地JSON进行离线模拟导入，或在折叠的开发区查看原始包。当前只接收`is_demo=true`，不是实际业务数据上传入口。新成员能查看授权项目包，不能接入或撤回；其他项目成员不能读取机场包。

## 页面与模块

| 页面 | 实现 |
|---|---|
| `/task-packages` | 项目与状态筛选、游标分页、当前可用标记、缺失提示 |
| `/task-packages/import` | 8类模拟场景、JSON离线导入、只读预检、同一接收服务 |
| `/task-packages/{receipt_id}` | 任务/人员/问题快照、事件、附件、版本差异、重试与撤回 |

代码位于`backend/modules/task_packages/`：`validation.py`负责严格JSON和B00校验；`service.py`负责接收幂等、版本、撤回、消费边界；`tasks.py`复用Procrastinate处理；`connectors.py`负责受控取件；`assessment.py`负责可用性判断；`views.py`组装只读详情和差异；`api.py`提供内部及A接口；`fixtures.py`生成模拟包。前端是`frontend/src/TaskPackages.tsx`，沿用已有界面体系。

没有复制A的任务管理、整改操作或人员账号系统。参与者和问题保持在校验后的snapshot中，B只保存事件与证据关系；不创建虚假的B02历史风险记录来代替A任务证据。

## 数据库及状态

冻结迁移：`migrations/versions/0005_b05_task_packages.py`。新增6张表：

| 表 | 作用与约束 |
|---|---|
| `task_packages` | 原始完整快照、哈希、包版本、项目/组织、接收状态；来源/任务/版本及来源/package_id各自唯一 |
| `task_events` | 包内event_id唯一；保留来源顺序、真实时间或null、人员角色、payload和evidence_refs |
| `task_package_assets` | 包内attachment_id唯一；保存可刷新取件标识、校验状态、文件ID和失败原因 |
| `task_package_streams` | 来源/任务唯一；最新接收版本、可用版本水位、当前包指针 |
| `task_package_requests` | 调用者/来源/操作/幂等键唯一，关联原接收包；submit与withdraw分开 |
| `task_package_invalidations` | 包撤回通知唯一；保留待B06/B07消费事件，不假装已处理下游 |

包版本使用BigInteger，符合B00安全整数范围。`package_version`来自A；`row_version`只用于B内部状态；两者不混用。

原始snapshot不因取件位置刷新而改写。正文哈希严格复用B00的RFC8785 JCS实现，仅排除exported_at和attachments.access_ref；保留数组顺序、package_id和其余业务字段。重复键、非有限数值、无效Unicode和不安全数字不能绕过校验。

接收状态为received→validating→processing→ready，异常failed，撤回withdrawn。ready只表示已完成可做的处理，**不等于资料完整或事实正确**。每次查询和下游取输入时重新检查附件是否仍可用，不能继续沿用旧“完整”标记。

最新接收版本与当前可用版本分开保存。只有ready且版本更高才能提升指针；新版本处理失败保留旧可用包，旧版晚到不会覆盖新版。撤回清空当前指针但保留最高可用版本水位，防止较旧包随后完成而复活旧版。

## 权限、重试与附件

- 新增固定`dev-a-service`模拟服务身份，只授予任务包范围动作，不授予普通知识加工/任务运行权限。正文org_id/producer/project_id不能扩大可信身份范围。
- 普通用户离线导入与模拟A提交共用receive；前端按钮隐藏之外，后端同样校验。内部导入允许管理员/加工员，撤回允许管理员/审核员。API、worker、重试和文件读取均重新加载或检查授权。
- 创建接收记录、幂等身份与队列插入共用事务，排队失败整体回滚。每个包的worker任务复用现有队列锁、心跳和恢复注册；事件、附件有业务唯一约束，按至少一次执行设计。
- 附件来自固定`demo-store`注册表，按项目隔离；不把包里的object_id解释为URL或Windows路径。流式读取校验类型、实际大小和SHA256，未通过校验不能生成可用证据。只在校验通过后原子写入项目受控目录和FileAsset。
- B05文件ID同时受包可用性保护，不能通过已有通用assets入口绕过包撤回。打开附件时再次检查当前授权、来源状态、文件存在与哈希。
- 同一业务包刷新取件标识时，只有通过连接器项目授权、文件大小/类型/哈希核对的位置才会更新传输表；不修改原始snapshot、不隐式新建job。失败包由有权限人员手动重试；已ready的部分资料包需要补充A的更高版本，不自动重跑或覆盖。
- 当前模拟连接器只读本仓库fixture文件，没有网络下载、签名URL、跨系统令牌刷新或真实附件传输的验收。协议接入点见[B05给A的接口说明](B05-A-integration.md)。

“中断后重试”通过明确的模拟扩展`b.mock_interrupt_once=true`注入一次已提交附件后的失败；只在demo包中运行。其他payload与扩展均作为数据保留，不当作可执行指令。

## 可供后续复盘使用的资料程度

- 没有过程事件：只标historical_summary；表示可供历史资料分析，不是已生成总结。
- 有事件但时间/声明不完整、包含未知事件或附件不可用：partial_timeline。
- 事件和时间声明完整、实际时间均已知、无未知事件、相关资料与附件通过校验且当前可用：complete_timeline输入条件。不能据此证明A没有漏报事件，更不能当作工程安全结论。

事件按来源数组顺序展示，时间未知保持null；不以exported_at补时。未知事件类型、payload和人员外部ID保留原文。版本差异包含字段变化、事件/附件新增移除、业务内容变化与来源顺序变化；已撤回旧包正文不进入对比。
