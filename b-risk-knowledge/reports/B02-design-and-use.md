# B02｜模拟数据接入与来源证据

本轮按“数据用模拟的数据”实现。CSV、Excel和治理导出是实际文件，接口、数据库、队列、增量处理和权限校验均实际运行。没有读取用户的真实报告、机场Excel、合并CSV或旧治理数据库。

## 直接试用

双击项目根目录“启动B模块.cmd”，打开 <http://127.0.0.1:5181/sources>。默认选择本地管理员。已为本次演示配置4个来源，并接入10条模拟记录：机场CSV 6条、机场Excel 2条、治理导出1条、地铁CSV 1条。它们是来源记录数，不是10个独立隐患。

全新环境会初始化模拟输入文件，进入来源页点“一键配置模拟来源”，再点来源卡片“开始接入”。无需准备或上传文件。默认不会自动把所有文件反复导入。

建议按以下顺序体验：

1. 机场CSV来源选择“CSV初始版本 · 6条”，预览显示39个原始字段、6条记录、2条需核查；提交后相同内容跳过6条。
2. 同一来源改选“CSV更新版本 · 仅修改1条”，会更新1条、跳过5条，总记录数不增加。点记录可切换v1/v2。再次导入v1会重新指向已有v1，不为相同内容重复造版本。
3. 选择“模拟接入2条后中断”，提交后可见已处理行及中断原因；点击“继续未完成行”接着处理，不增加重复结果。此选项仅为明确的本地故障演示。
4. 机场CSV选择“CSV异常演示 · 3条”，范围不匹配和身份缺失行会失败，合法行继续处理。新增+更新+跳过+失败始终等于已处理行数。
5. 打开治理导出记录，对比原始描述与人工生效描述，展开来源信息查看第7版修订、模拟审核员和字段来源；B不回写旧系统。
6. 打开记录详情的图片区，查看现场照片类型、文字截图类型、锚定/候选关系、不可用附件。可用图片是明确标注的示意图，不是真实照片或报告截图。
7. 对比跨来源候选，管理员确认重复后“确认关联后的明细组”减少，原始记录均保留。候选不是事实；比较版本变化后旧确认失效。地铁同描述记录不会被跨项目删除或关联。
8. 切换“其他项目成员”，只能看到地铁项目；切换“新成员”，可读机场记录和图片，不能导入或确认重复。原始整表下载仅对加工权限开放，避免学员获取未经逐行筛选的完整输入。

## 页面与接口

| 页面 | 行为 | 对应接口（/api/v1） |
|---|---|---|
| `/sources` | 三类来源、固定映射模板、最近同步、可选手动配置 | `GET/POST /sources` |
| `/imports/new` | 选择受控文件ID、字段映射、全量异常统计、前20行预览 | `GET /input-files`、`POST /imports/preview`、`POST /imports` |
| `/imports` | 批次分页列表 | `GET /imports` |
| `/imports/{id}` | 计数、输入哈希、规则版本、错误行、继续处理 | `GET /imports/{id}`、复用B01的`POST /jobs/{job_id}/retry` |
| `/records` | 项目/来源/类型/质量/日期筛选、游标分页、分别计数 | `GET /records` |
| `/records/{id}` | 原文/生效值、历史版本、治理来源、报告缺失提示、图片和重复候选 | `GET /records/{id}?version=`、`GET /evidence/{id}`、`POST /record-links/{id}/confirm` |

创建来源返回201；导入返回202和`id`、`job_id`；同幂等键同体重放返回200，异体409；重复提交使用新的幂等键会创建新的可核对批次，内容增量仍由记录/版本唯一约束保证。预览不创建来源记录、版本或批次。

## 代码与数据库

`backend/modules/ingestion/`包含接入器、服务、API、任务、模拟文件注册和模型；前端页面独立在`frontend/src/Ingestion.tsx`，复用B01布局。新增迁移`0002_b02_sources.py`和8张表：任务书的7张表，加用于逐行恢复和对账的`import_rows`。B01的权限、审计、任务队列、文件表和迁移入口继续复用。

| 实现 | 保证 |
|---|---|
| `data_sources` | 项目+命名空间唯一；保存映射模板版本及实际映射，API不接受服务器路径 |
| `import_batches` | 冻结输入资产、SHA-256、映射、规则版本；保留实质计数 |
| `source_documents` | 来源+报告外部ID唯一；未提供报告文件时哈希/附件为空，界面明确不可用 |
| `source_records` | 来源+外部ID唯一；项目、类型、质量、日期为可查询列 |
| `source_record_versions` | 记录+版本号及记录+内容哈希双唯一；原文、生效值、来源、异常分开 |
| `evidence_items` | 固定到来源版本；保存行/工作表/单元格定位、图片类型、关系可信度及受控资产ID |
| `record_links` | 只生成同项目同类型候选；确认须审核权限和当前row_version，绑定被比较版本 |
| `import_rows` | 批次+输入行唯一；行处理结果和业务变更同事务，重试跳过已完成行 |

内容哈希包含原始字段、生效字段和治理修订，不包含整文件哈希，因此单条内容修改不会为整表制造新版本。文件哈希另外保存在批次及版本来源中。相同内容重复接入的每次出现仍可通过`import_rows`追溯。

队列仍由Procrastinate调度。来源导入任务使用来源级队列锁，不同来源可以并行，同来源串行；逐行提交事务保存记录、版本、证据、行账本和计数。故障重试在同一事务中同时恢复业务任务与批次状态。B01通用停滞任务恢复也注册了`b02.source_import`。

稳定ID缺失时，只允许“项目+报告ID+来源原始序号”后备身份并提示核查。没有原始序号则拒绝该行，不用当前行号或可变描述生成身份。

## 三类接入器的实测边界

- CSV：Python标准库读取UTF-8/UTF-8 BOM；模拟39列完整保留，包括未映射字段、坏images及不可信指令文本。39列是本次模拟合同，不声称已核对真实合并CSV表头。
- Excel：openpyxl读取第一个工作表，保留原始列、工作表名、行号和如`A2:I2`的单元格范围。图片关系读取模拟导出中的显式行锚点。真实Excel嵌入图片提取、多工作表合并、合并单元格和旧工作台图片规则仍需真实样本适配，未在本轮验收。
- 治理导出：读取`governance-export-v1` JSON，保留`raw_fields`、`effective_fields`、原来源ID、修订号、修改人和字段来源。仅有效业务值覆盖原值，项目和身份字段不允许由生效值扩大。未连接旧工作台数据库。
- 校验复用Pydantic，收集逐行枚举、类型、日期、身份、范围和images异常。未额外引入pandas/Pandera；当前小批量验证不需要两套重复校验依赖。
- 文件注册当前仅开放受控模拟文件目录；未实现通用文件上传或任意目录扫描。首版输入上限5MB/10000行，未做全量历史库容量压测。

开源组件仅新增锁定的openpyxl 3.1.5（MIT），读取器参考[官方教程](https://openpyxl.readthedocs.io/en/stable/tutorial.html)。校验复用已有Pydantic，参考[模型文档](https://docs.pydantic.dev/latest/concepts/models/)。权限、数据库、迁移和队列复用B01，不引入第二套平台。
